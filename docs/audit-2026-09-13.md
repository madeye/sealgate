## Findings

### F1 — P2: Proxied TLS handshakes ignore cancellation

Source: [src/http.ts, lines 37–44](../src/http.ts), with abort-listener removal in
[src/proxy.ts, lines 94–99](../src/proxy.ts).

After CONNECT succeeds, `connectViaProxy` removes its abort handler. The TLS
socket created next has no abort handler, and the HTTP client's connection
callback runs only after `secureConnect`. If a proxy acknowledges CONNECT but
the destination stalls its TLS handshake, aborting the request neither settles
the request promise nor closes that socket.

**Reproduction:** a loopback proxy sends HTTP 200 and receives a TLS ClientHello,
then deliberately stalls. Abort is triggered; 500 ms later the promise remains
pending and one proxy socket remains open. Destroying the fixture socket finally
settles the request. Reproduced under Node 22 and Node 25.

**Impact:** detector timeout, chat cancellation and gateway deadlines cannot
finish this request. Repeated stalled requests can occupy both gateway slots;
an affected command can remain alive beyond its configured timeout.

**Fix direction:** maintain abort coverage through TCP, CONNECT and TLS setup;
destroy the in-progress socket and complete the connection callback exactly once.
Add a regression that acknowledges CONNECT, stalls TLS, and checks rejection and
socket closure on cancellation.

### F2 — P2: macOS tool forwarding discards configured proxy authentication

Source: [src/proxy.ts, lines 136–146](../src/proxy.ts), invoked by
[src/sandbox.ts, lines 187–193](../src/sandbox.ts).

The macOS forwarder uses only the configured proxy's hostname and port and pipes
client bytes unchanged. The sandbox receives a credential-free loopback proxy
URL, so neither endpoint adds the configured `Proxy-Authorization` header.

**Reproduction:** configure a synthetic authenticated loopback proxy. A CONNECT
through the macOS forwarder has no authentication and receives HTTP 407. Calling
`connectViaProxy` directly with the same configured URL supplies authentication
and succeeds. Reproduced under Node 22 and Node 25.

**Impact:** `sealgate claude --proxy-egress` fails for tools behind an authenticated
HTTP proxy even while the gateway itself works through that proxy.

**Fix direction:** parse tool HTTP/CONNECT requests and inject credentials on the
host side, as the Linux forwarder does. Cover both CONNECT and ordinary HTTP
with an authenticated mock proxy.

### F3 — P2: Malformed proxy credential escapes crash the host process

Source: [src/proxy.ts, lines 116–123](../src/proxy.ts), URL validation at lines 22–30.

`parseProxyUrl` accepts a password containing a malformed percent escape, such as
`http://user:%@127.0.0.1:PORT`. `decodeURIComponent` subsequently throws inside
the socket's asynchronous `connect` event listener. This exception occurs outside
the promise executor and is not converted into a rejected request.

**Reproduction:** a subprocess connects through that synthetic proxy URL with a
surrounding promise `try/catch`. It exits with code 1 and an uncaught
`URIError: URI malformed`; the promise catch is never reached. Reproduced under
Node 22 and Node 25.

**Impact:** a malformed local proxy setting terminates the entire CLI/gateway
instead of reporting a controlled configuration error and running normal cleanup.
This is a configuration-triggered crash, not a demonstrated remote exploit.

**Fix direction:** validate/decode credentials before opening a socket and reject
malformed encoding through the normal sanitized error path.

### F4 — P2: macOS detached tools survive launcher exit

Source: [src/launcher.ts, lines 32–41](../src/launcher.ts),
[src/seatbelt.ts, line 111](../src/seatbelt.ts), and
[src/sandbox.ts, lines 199–202](../src/sandbox.ts).

`foreground` waits for the immediate child and forwards signals only to that
child. The macOS launch cleanup closes services and deletes runtime files but
does not terminate surviving descendants. A tool can detach with ignored stdio
and outlive a normally exiting native client.

**Reproduction:** run a sandboxed harness that starts a detached shell, unrefs it
and exits. The launcher returns 0 and the runtime directory is removed. One
second later the shell writes a synthetic file in the scratch workspace.
Reproduced under Node 22 and Node 25 on macOS.

**Impact:** background tools can continue consuming resources and modifying the
project after the session ends. They retain their Seatbelt restrictions; this
probe does not demonstrate escape from those restrictions.

**Fix direction:** supervise the entire session's descendants and terminate them
before reporting shutdown complete. A process-group-only solution must also
address children that create their own session. Test normal exit and cancellation
with detached descendants, and keep the child lifetime bounded in the test.

## Remediation follow-up

The subsequent `fix/audit-proxy-and-session-cleanup` branch fixes F1–F4 and both
maintenance observations. The findings above describe the original audited
revision. The retained probes now show cancellation settling with zero open
sockets, authenticated forwarding succeeding, malformed credentials reaching the
normal catch path, and no workspace write after session exit.

Regression coverage includes a stalled TLS handshake, malformed percent escapes,
authenticated CONNECT and chunked HTTP, detached double-forked macOS tools,
cancellation of an unresponsive client, and isolation from unrelated processes
and concurrent sandbox sessions. The supervisor also rejects unconfined execution.

CI was independently added to main in PR #3 while remediation was in progress.
The remediation branch uses that workflow, covering Linux/macOS and Node 22/24,
with separate platform integration jobs using pinned native Claude 2.1.270 and
synthetic credentials, and adds explicit type checking.
Plugin and website versions now agree with the 0.4.0 package. Hosted workflow
execution and Linux Docker integration still require verification on Linux.

Final local validation on the remediation branch:

  integration tests skipped; explicit macOS suite 7 passed, 0 skipped on each.
- TypeScript type checking, `actionlint`, strict Claude plugin validation,
  `npm pack --dry-run`, and whitespace checks passed.
- The package includes both compiled supervisor modules, now explicitly required
  by the package verification script.
